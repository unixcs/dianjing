# 重构验收测试报告（本地全链路）

> 日期：2026-10-05 ～ 2026-10-25（feng-1 Windows 本地）
> 范围：电竞小程序重构版（原生小程序 + Go 后端）在正式提审/发布前，对**全部功能模块**的三层验收测试。
> 结论：**三层全部通过** —— API E2E 71/71、小程序 UI 自动化 28/28、商家后台 UI 50/50。发现并修复 **2 个真实 bug**（其一为发布级白屏阻断）。

---

## 一、测试对象与环境

- 被测后端：`backend/`（Go 单二进制，`./server.exe -config dianjing.env.dev`，监听 127.0.0.1:8096）
- 被测前端：`miniapp/`（微信开发者工具 + miniprogram-automator 驱动）
- 被测管理后台：`backend/internal/api/admin_static/index.html`（go:embed 单文件，`/v2/admin`）
- dev 配置：`backend/dianjing.env.dev`（**全 dummy 值可入库**；WX_APP_ID=wx0000…、XPAY_* =dummy、沙箱模式）
- 测试数据：`./seeddev.exe <data-dir>` 一键重建（分类/服务/封面图/用户/公告/协议），`./tokenforge.exe -env dianjing.env.dev -u <uid> -d <days>` 铸用户 token
- 微信侧依赖的替代：「假微信双通道」——用户态用 tokenforge 注入；支付/退款结果用签名推送（`/wx/msg`，sha1 签名）在服务端收敛资金态。**不需要真实 AppKey/微信支付商户号即可测全链路。**

## 二、三层测试结果

### 1. API E2E —— 71/71 通过（`node tools/e2e-api.mjs`）

覆盖：公开接口（home/services/categories/docs）、注册登录、下单、支付参数（paySig/signature/mode=short_series_goods/signData.env）、支付推送收敛（待联系）、取消流、服务流转（1→2→3）、退款申请/审核拒绝/审核通过/推送收口/已退款、风控放行、反馈、管理端全套、未登录/越权/重放等负向。

**抓到 Bug ①（安全）**：`GET /uploads/` 返回目录列表 —— `noDirListing` 只拦了以 `/` 结尾的路径，而 StripPrefix 后目录根请求到达时 path 为**空串**。已修复（`backend/cmd/server/main.go`：空路径与 `/.` 一并拒绝）。

### 2. 小程序 UI 自动化 —— 28/28 通过（`node tools/e2e-miniapp.js`，Jiaofu 工作流移植）

借基准仓（Jiaofu）的完整工作流：devtools `cli.bat auto --auto-port 9420` + automator connect + 可观察状态断言 + `tools/artifacts/` 截图与 JSON 报告。覆盖：

- 首页（公告/banner/分类位/服务卡）→ 卡片 tap 跳详情 → 详情字段
- 下单 happy path：数量×2 合计联动、真实 input 输入联系方式、`wx.requestVirtualPayment` **mock 捕获断言**（paySig/signature/orderNo/env）
- 支付推送 → 订单详情=待联系（can_refund/refund_mode）
- 支付取消流（mock cancel）→ 待支付 → 用户取消 → 已取消
- 退款流（showModal mock）→ 退款中 → 推送收口 → 已退款
- 订单列表五 tab 过滤（tap 真实触发 + evaluate 兜底）、金额格式化
- 退款记录页、意见反馈提交、协议文档与 API 全等、我的页资料

**抓到 Bug ②（发布级阻断）**：`app.wxss` 第 1 行用了 `//` 注释 —— **WXSS 不支持 `//`**，编译失败导致**整个小程序所有页面白屏**（页面栈为空、appLaunch 超时）。模拟器截图定位，改 `/* */` 修复。这也证明 tx 上重构的小程序从未在开发者工具里编译过——本次验收的必要性直接得到印证。

> automator 踩坑记录已写在 `tools/e2e-miniapp.js` 头部注释（page.callMethod 对生命周期失效、Node≥18.20.2 spawn EINVAL 只能 connect、编译缓存损坏需 cli quit 重开、断言只用可观察状态）。

### 3. 商家后台 UI —— 50/50 断言通过（浏览器自动化；完整断言清单见下方表格，本地产物在 `tools/artifacts/`〔不入库〕）

对齐原版后台裁剪后的 7 个区块全覆盖：

| 区块 | 验证点 |
|---|---|
| 登录/总览 | 错密码报错、对密码进入、9 项统计渲染、token 持久化、刷新自动恢复会话、401 自动登出 |
| 服务商品 | 列表渲染、新增对话框全字段、编辑部分更新（只改价不丢标题）、下架/上架（公网同步可见/隐藏） |
| 分类 | 列表、添加、排序落库 |
| 订单 | 列表、状态筛选（每档全匹配）、开始服务 1→2、完成 2→3、操作列按钮随状态显隐 |
| 退款 | 仅状态 1/2 可申请（负向 400）、待审核行、同意/拒绝按钮、拒绝（prompt 备注）→订单回服务中、再申请→同意→已批准→**签名推送收口=已退款**→订单已退款→**风控列「已退款放行」**→总览联动 |
| 反馈 | 列表、回复落库=已回复、prompt 取消不执行 |
| 公告/协议 | 设置回填=API 全等、非法 Banner JSON 拦截、保存后公网 home 公告+banner 生效（/uploads 路径自动绝对化）、还原 |

**Harness 限制（如实记录）**：本环境 IAB 浏览器沙箱不向页面投递真实输入事件（CDP Input/CUA 坐标点击均不达，事件探针为空），且禁用光栅截图。因此按钮验证采用**页内 `element.click()`（派发真实 DOM 事件，触发真实 onclick）+ 直调页面全局处理函数**，断言全部基于渲染后 DOM 与服务端终态 + 公网 API 交叉验证。OS 级输入路由属 harness 属性，非应用属性，不影响功能结论；上线前建议人工在真机/桌面浏览器点一遍关键按钮（登录、新增服务、开始服务、同意退款、保存设置）作双保险。

## 三、遗留观察项（不阻断）

1. **P3：后端允许重复分类名**（UI 重复添加同名分类会静默创建第二行）。原版行为未对比；H5 端仅多显示一个同名 tab，无功能影响。如需对齐原版可在 `POST /v2/api/admin/categories` 加唯一校验。
2. admin 保存 banner 后公网返回的 `image` 会从 `/uploads/x.png` 绝对化为完整 URL —— 是后端有意行为（H5 需要），UI 断言需按绝对化比较。
3. dev 库测试遗留（均无碍，`seeddev` 重跑即清）：服务 #8「自动化测试服务」、分类 #6/#7「自动化分类」、订单 #18（已退款）/#19（已完成）、一条反馈已回复。

## 四、复跑方式（接手必读）

```bash

cd backend && ./seeddev.exe ./data && ./server.exe -config dianjing.env.dev &
# 1) API E2E
node tools/e2e-api.mjs
# 2) 小程序 UI E2E：先开开发者工具自动化端口
"/d/Program/soft/wechattools/cli.bat" auto --project "D:/mnt/Projects/dianjing/miniapp" --auto-port 9420
node tools/e2e-miniapp.js        # 产物在 tools/artifacts/（截图+报告 JSON）
# 3) 管理后台：浏览器开 http://127.0.0.1:8096/v2/admin，dev 密码见 dianjing.env.dev 的 ADMIN_PASSWORD_HASH 明文 admin-dev-2026
# 4) Go 单测/vet
cd backend && go vet ./... && go test ./... -count=1
```

注意：`tools/e2e-miniapp.js` 顶部有 automator 的踩坑注释；E2E 会 mock `requestVirtualPayment`/`showModal` 并用 tokenforge 注入用户态，**不会真实扣款**。

## 五、结论

重构版小程序三层验收全绿：前端 10 页全部功能模块、下单-支付-退款资金闭环（含推送收敛与风控放行）、商家后台 7 区块全部按钮/表单/对话框功能正常，与裁剪范围一致。2 个已修 bug 建议随下次发版带上（其中 app.wxss 白屏属必须在发布前修复项，**已修**）。可进入提审流程（提审/发布由项目所有者在微信平台亲自操作）。
